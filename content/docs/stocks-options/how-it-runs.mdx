## Schedule

All times are New York time, so they move against Sydney clocks at each daylight-saving change.

| Job | When | What |
|---|---|---|
| `routine` | Mon to Fri 07:30 | Pre-market scan in four stages; no broker calls |
| `paper-b` | Mon to Fri 08:30 | Robot B (paper): the stocks strategy on its paper account |
| `forward` | Mon to Fri 12:40, waits for the close plus 20 minutes | Forward test of registered trials |
| `weekly` | Fri 20:00 | Weekly scorecard |
| `dashboard` | Every 5 minutes in session, 15 otherwise | Builds and sends the status snapshot |
| `options-live` | Same rhythm, one minute later | Option positions, open interest, rule states |

The crypto jobs left the schedule when the [crypto desk](/crypto) was closed on 2026-10-24. Six more jobs run
beside these: the Options clone (paper)'s session and nightly review, the options pipeline check, the deploy notice
and automatic deploy, and a weekly read of the economic release calendar (Fridays 21:30) for the Calendar page.

One more timer sits outside that table. `wt-webull-pull.timer` reads your own Webull account, read only, every 2
minutes from 09:00 to 16:58 on weekdays, and once at 17:40 every day. It is off until the owner's cutover; until
then a cloud routine writes the Trades journal.

## Host

- One cloud server runs every job as generated service units.
- The Webull read runs as its own user, `wt-webull`, from a copy of its code the owner installs by its hash. It
  is the only job that can read the Webull key. A second job, as the usual user, sends what it read to the site.
- The Mac runs nothing. Its old checkout is kept only as a fallback.
- Every job goes through one runner with a lock, a pre-flight check, a deadline and a heartbeat.

## Deploys

- Work lands on `integration`, which deploys a staging site with synthetic data. `main` is production.
- Where the owner has switched it on, the host deploys the newest green `main` itself, once an hour.
- A change to units, host helpers, the deploy code or the Webull code waits for the owner.
- The gate is computed: it checks that required checks passed on the commit and that no session is in progress.
- The host refuses a deploy when the live status site is older than the snapshot format the new code sends.

## When something goes wrong

Runbooks cover: kill and flatten, not flat at the close, latch reset, rollback, disk full, status site late,
dead-man switches, secret rotation, backups, position alerts, the options live job, keys and data feeds, the feed
agreement report, the public-repository guards, the read-only Webull job, the board feed, the cloud routines and the
options clone. See [runbooks](/stocks-options/runbooks).
